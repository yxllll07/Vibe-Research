# 交易系统 v2:情绪周期 + 主线 + 龙头(TRADER_v2)

> 研究 / 纸面用,不是投资建议。v2 按短线交易者的读盘框架重写;规则里没有用收益拟合任何参数。
> 写规则前看过 2026-06-23、07-03 两天的复盘,所以全期结果以验证期为主,2026-04~10 已揭盲只作参考。

## 模块

| 模块 | 文件 | 内容 |
|---|---|---|
| 情绪周期 | `structure/sentiment.py` | 涨停 / 跌停 / 炸板率 / 昨日涨停今日表现 / 各级晋级率 / 最高板 / 高位大面 → 过去 60 日分位 → 冰点、修复、发酵、高潮、分歧、退潮、震荡 |
| 主线 | `structure/theme.py` | 申万二级行业(按时点):近 3 日加权涨停、5 日持续性、最高板、3 日涨幅 → 主线分,前 3 且热度 ≥4 为主线 |
| 龙头 | `structure/theme.py` | 主线内:高度、10 日涨停次数、抗分歧、率先启动、容量 → 龙头 / 前排 / 跟风;空间龙 = 全市场最高板 |
| 五模式 | `candidates/modes_v2.py` | A 主线首板预判、B 主线 1 进 2、C 主线龙头 / 空间龙首次分歧、D 核心分歧转强、E 主线趋势中军;每个模式有情绪开关,退潮 / 冰点不开新仓 |
| 退出 | `system/strategy_v2.py` | A/B/D 次日开盘卖,仍封涨停则续持;C 持 2 日、E 持 5 日,−5% 止损 |
| 复盘 | `system/review_v2.py` | 情绪周期 → 梯队 → 主线与龙头 → 计划 → 执行 → 事后验证 |

命令:`python -m ashare_lab structure`、`python -m ashare_lab review-v2 --date D`、`python -m ashare_lab history-v2 --start … --end …`

## 为什么:读对了盘,买错了时点

v2 各模式前 3 名在全期的平均收益分解(%):

| 模式 | D 收盘 → T 开盘 | T 开盘 → T 收盘 | T 收盘 → T+1 开盘 |
|---|---|---|---|
| B 主线首板 | **+1.71** | −0.25 | −0.37 |
| C 龙头首次分歧 | **−2.02** | +0.83 | **−1.84** |
| D 分歧转强 | −1.80 | +0.80 | −1.37 |
| E 趋势中军 | −1.08 | +0.40 | −0.74 |

- 主线首板的次日溢价(+1.7%)发生在**集合竞价开盘那一下**,属于 D 日打板的人;T 日开盘再买已经付完溢价。
- 龙头 / 核心股在 T 日**盘中**平均是涨的,但两端隔夜都在跳空下跌;T+1 规则下开盘买、持有过夜,正好吃到亏的那一段。
- 也就是说,这套打法的利润在**执行环节**(D 日打板的价格、9:25 竞价判断、盘中低吸点位),日线回测只能用「次日开盘价」近似,恰好错过。
- M0 学到的「短期反转」是同一件事的统计面:热门股在次日开盘被高估。

## 下一步

1. **分钟 + 竞价数据**是这套打法能不能成立的关键。腾讯分钟线只给最近 320 根(5 分钟约 6 个交易日),东财分钟历史在本环境连接被重置;
   需要 Tushare 分钟 / `stk_auction` 权限,或在本机网络取东财分钟历史。
2. 有了分钟数据后按交易者的真实执行建模:B 用 D 日封板价 + 排队成交假设(保守 / 乐观两档);C / D 用 T 日盘中低吸(如开盘后 30 分钟均价)。
3. 情绪周期 / 主线 / 龙头三个模块保留,作为读盘与风控层(退潮 / 冰点不开新仓在两天复盘里都起了作用)。
